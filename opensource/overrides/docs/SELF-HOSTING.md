# 自建账号服务

1. 创建你自己管理的 Supabase 项目。
2. 在自己的 SQL Editor 中执行 `supabase-auth-migration.sql`，再执行
   `supabase-auth-security-migration.sql`。这些文件位于本目录。
3. 首次迁移会生成一次性初始化码；仅在自己的后台保管，用应用初始化管理员。
4. 通过 `BLUEV_OSS_SUPABASE_URL`、`BLUEV_OSS_SUPABASE_ANON_KEY` 配置自己的项目。
   只使用 publishable/anon key，绝不把 service-role key 放进客户端。
5. 创建自己的品牌及成员授权。默认没有原组织的品牌或用户数据。

云端日志同步在社区模板中默认关闭；这里没有提供匿名读取全表的日志策略。
如果需要多机日志和反馈功能，应自行设计有服务端身份与归属校验的表和 RPC，
审核权限后再启用。云端认证、反馈、统计不是同一套数据表，不能仅初始化账号就
假设所有云端功能都已部署完成。

这些迁移来自共享业务逻辑，已在隔离数据库做过权限回归；部署到自己的项目后仍应
检查实际权限和限流设置。不要把迁移文件当成针对所有部署环境的安全保证。
